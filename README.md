# 키움 멀티 트레이딩 데스크 (프로토타입)

TypeScript 서버와 Lightweight Charts **5.2.0** 기반 대시보드입니다. 기본 모드는 가상 시세를 사용하는 데모입니다. 키움 모의/실전 **조회**를 선택할 수 있지만, 주문은 어떤 모드에서도 증권사에 전송하지 않습니다. 실거래 완제품이 아니며 실제 투자에 사용하지 마세요.

## 실행

Node.js 20 이상에서:

```bash
npm install
cp .env.example .env
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다. 기본 데모에서는 가상의 조건검색 결과와 캔들이 표시됩니다. `npm run build`, `npm test`로 타입 검사/빌드 및 테스트를 실행합니다.

## 키움 조회 설정

`.env`의 `KIWOOM_MODE`를 `mock` 또는 `real`로 설정하고 해당 환경의 `KIWOOM_APP_KEY`, `KIWOOM_SECRET_KEY`를 입력한 뒤 서버를 재시작합니다. 키움 포털에서 API 사용 신청, 환경별 키와 필요한 네트워크/IP 허용 설정을 먼저 확인하세요. 화면에서 **목록 불러오기**를 누르고 조건식을 선택한 후 설정을 적용합니다. 조건식은 키움 HTS에서 미리 만들어야 합니다. 모의 환경의 조건검색/시세 지원 여부는 키움 정책에 따라 다를 수 있습니다. 자격 증명은 서버에서만 사용하며 `.env`는 Git에서 제외됩니다.

키움 공식 저장소의 [REST API 명세 및 예제](https://github.com/Kiwoom-Securities/Kiwoom-REST-API)를 참조했습니다: OAuth `au10001`, 조건식 목록/일반검색 `ka10171`/`ka10172` (WebSocket), 체결강도 `ka10046`, 1분봉 `ka10080`. 조건검색 페이징을 처리하고 각 종목의 체결강도/누적거래대금을 조회합니다. 조회 실패 시 이전 데이터가 남고 오류가 표시됩니다. 대금은 키움 응답의 원래 단위이며 API 명세에서 단위를 확인해야 합니다.

## 동작 및 제한

- 서버 하나가 모든 조회를 직렬 큐로 관리하며 기본 요청 간격은 300ms입니다. 이는 키움의 실제 호출 제한을 보장하지 않습니다. `.env`에서 더 느리게 조정하고 키움의 계정별 제한을 확인하세요. 여러 서버 프로세스 간 제한은 공유되지 않습니다.
- 검색 결과 전체를 대상으로 등락률, 체결강도, 누적거래대금의 백분위 순위를 가중 평균하여 상위 10개를 표시합니다. 동점은 같은 백분위이며 종목코드 순으로 정렬합니다. 상위 N개 차트에 동일한 5/20 이동평균을 표시합니다.
- 60초마다 조건검색과 선택 종목 캔들을 다시 조회합니다. 실시간 WebSocket 체결 스트림이 아닌 **폴링**이며 종목이 많거나 제한에 걸리면 60초보다 오래 걸릴 수 있습니다. 중첩 갱신은 생략합니다.
- 전략 시작 시 확정된 1분봉의 MA 5/20 교차를 종목당 한 번 평가하여 1주 가상 매수/매도를 기록합니다. 현재 봉은 제외합니다. 기존 보유 종목이 상위 N개에서 빠지면 해당 종목의 전략 평가는 중지됩니다. 가상 포지션과 이벤트는 메모리에만 보관되어 재시작 시 사라집니다.
- 실제 주문, 주문 체결/취소, 잔고 동기화, 손절/일일 손실 한도, 장애 복구, 지속 저장 및 실시간 체결 구독은 구현되지 않았습니다. 따라서 무인 자동매매에 적합하지 않습니다. `real`은 실전 **조회만** 의미합니다.
- 이 프로토타입에는 사용자 인증이 없습니다. 신뢰할 수 없는 네트워크에 노출하지 마세요. 미리보기 URL 또한 접근 권한이 있는 사람에게만 공유하세요.
