# 키움 멀티 트레이딩 데스크

TypeScript와 Lightweight Charts **5.2.0** 기반의 키움 조건검색·실시간 시세·분봉 조회 프로토타입입니다. 실시간 WebSocket과 REST를 중앙 관리자가 단독으로 제어합니다. 가상 시세는 제공하지 않습니다. `real` 또는 `mock` 환경의 키움 데이터만 조회합니다. **어떤 모드에서도 증권사 주문을 전송하지 않습니다.** 전략 이벤트는 조회한 데이터로 계산한 메모리상 모의 결과이며 실거래용이 아닙니다.

## 설정 및 실행

Node.js 20 이상이 필요합니다.

```bash
npm ci
cp .env.example .env
# .env에 해당 환경의 키움 App Key와 Secret Key를 입력
npm run dev
```

Windows PowerShell에서는 `Copy-Item .env.example .env`를 사용하세요. 브라우저에서 `http://localhost:3000`을 엽니다. `.env`는 Git에 포함되지 않으며 키는 서버에서만 읽습니다. 키를 채팅이나 GitHub에 올리지 마세요.

`.env`의 `KIWOOM_MODE=real`은 실전 서버의 **조회**, `mock`은 모의 서버의 조회를 의미합니다. 환경별로 발급된 키가 다릅니다. 키움 API 사용 신청과 IP 허용 등 포털 설정을 확인하세요. 모의투자 서버에서 조건검색이나 해당 시세 API의 지원 여부는 키움 정책을 확인해야 합니다. 조건식은 영웅문4에서 미리 만들어야 합니다.

화면에서 **목록 불러오기** → 조건식 선택 → **설정 적용** 순으로 사용합니다. 키 미설정, 인증 실패, 조건검색 실패 또는 시세 누락 시 오류가 표시되며 대체 가상 데이터는 만들어지지 않습니다. 이전 성공 데이터가 남아 있을 수 있으므로 마지막 업데이트 시간을 확인하세요. 조건식 변경 시에는 이전 데이터가 지워집니다.

## 데이터와 제한

[키움 공식 REST API 저장소](https://github.com/Kiwoom-Securities/Kiwoom-REST-API)의 명세를 참조합니다: OAuth `au10001`, 조건식 목록/일반검색 `ka10171`/`ka10172` (WebSocket), 체결강도 `ka10046`, 분봉 `ka10080`. 등락률은 조건검색 고정소수점 응답을 퍼센트로 변환하고 누적거래대금은 명세의 **백만원** 단위로 표시합니다. 차트 시간은 한국 시간입니다.

- 검색 결과의 등락률·체결강도·누적거래대금 백분위에 **사용자가 설정한 가중치**를 적용하여 지정한 개수(1~40)의 상위 점수 종목을 목록에 표시합니다. 목록은 설정한 주기(15초~5분)로 다시 계산합니다. **체크한 종목만** 멀티차트에 그려지고, 모의 매매 평가도 그 종목에만 적용됩니다(최대 10개). 주식 종목코드만 대상으로 합니다. 필수 시세가 없는 종목은 순위에서 빼고 경고로 남깁니다.
- 모든 REST 호출은 중앙 관리자의 토큰 버킷을 통과합니다(전체·API별·주문 레인 분리). `KIWOOM_REQUEST_INTERVAL_MS`의 기본 300ms와 함께 쓰이는 수치 예산은 **로컬 안전값이며 키움 공개 한도가 아닙니다**. 여러 프로세스 간 제한은 공유되지 않습니다.
- 시세는 **실시간 WebSocket 구독**으로 갱신됩니다. 분봉은 REST(`ka10080`)만 신뢰할 수 있어, 선택 종목(최대 10개)에 대해서만 새 분(minute) 시작이 감지되거나 `CANDLE_SYNC_MS`(기본 60초)가 지났을 때 재조회하며, 실시간 체결로 분봉을 만들어내지 않습니다. 분봉은 단일 응답 페이지만 사용합니다.
- 전략은 확정된 1분봉의 MA 교차에 대해 가상 매매를 기록합니다. 보유 종목이 상위 N개에서 빠지면 평가가 중지되고, 재시작하면 가상 포지션과 이벤트는 사라집니다.
- 실제 주문·체결·취소·잔고 동기화는 구현되지 않았습니다. 모의 진입만 로컬 위험 한도(보유 수, 일일/종목당 횟수, 연속 손실, 쿨다운, 당일 실현 손실 %, 분당 요청)로 제한하며, 이 수치는 **키움 정책이 아닙니다**. 실시간 연결의 재연결·구독 복원만 구현되어 있습니다. 실계좌 자동매매에 사용하지 마세요.
- 웹 대시보드에 사용자 인증이 없으므로 신뢰할 수 없는 네트워크에 노출하지 마세요.

`npm run build`로 타입 검사 및 빌드, `npm test`로 단위·통합 테스트를 실행합니다. 실제 계정 연결은 발급받은 키와 키움 네트워크 접근이 필요하며 별도 확인해야 합니다.


## 실시간 중앙 관리자

`server/realtime/`가 브로커 접근을 단독으로 소유합니다. 화면·전략은 `DemandBridge`만 사용하고, 허브나 키움 클라이언트를 직접 호출하지 않습니다.

| 모듈 | 책임 |
|---|---|
| `protocol.ts` | 공식 명세 기반 패킷 생성/해석(`LOGIN`, `REG`, `REMOVE`, `REAL`, `PING`), FID 필드 매핑 |
| `hub.ts` | 단일 WSS 세션 상태기계, 로그인/유지/재연결(지수 백오프+지터), 구독 참조 카운트, 요청/응답, 무응답 감시, 중복 억제, 모의 신호·포지션, 감사 기록 |
| `cache.ts` | 종목정보·체결·분봉 링버퍼·업종·조건검색 포착 종목 공유 캐시 |
| `limits.ts` | REST 토큰 버킷(전체/API별/주문), 실시간 연결·구독·패킷 상한, 오류 코드 분류 |
| `audit.ts` | 상태·연결·구독·한도·신호·포지션·주문(없음) 감사 로그 |
| `bridge.ts` | 수요 로직용 단일 창구: 조건검색, 순위, 캔들, 구독 동기화, 시세 신선도 |
| `plan.ts` | 선택 종목 우선 + 포착 종목 로테이션. 구독 상한 초과분은 건너뛴 수로 보고 |
| `risk.ts` | 모의 진입 차단만 수행. 청산은 막지 않음. 주문 전송 없음 |

### 공식 명세로 확인한 사실

근거: [키움 공식 REST API 저장소](https://github.com/Kiwoom-Securities/Kiwoom-REST-API)의 `kiwoom/core/ws_client.py`, `kiwoom/realtime/packets.py`, `kiwoom/_data/kiwoom_api_spec.json`.

- 엔드포인트: 실전 `wss://api.kiwoom.com:10000/api/dostk/websocket`, 모의 `wss://mockapi.kiwoom.com:10000/...`
- 로그인: `{"trnm":"LOGIN","token":...}` → 서버가 `trnm=LOGIN` + `return_code`로 응답. 그 전에는 다른 프레임이 오지 않습니다.
- 유지: 서버가 보내는 `PING`(JSON 또는 문자열)을 **수신한 그대로 되돌려** 보냅니다. 공식 클라이언트는 `ping_interval=None`으로 접속합니다.
- 등록/해제: `REG`/`REMOVE` + `grp_no`, `refresh`, `data[{item,type}]`.
- 실시간 프레임: `{"trnm":"REAL","data":[{"item","type","values":{fid:값}}]}`.
- 사용 중인 타입과 실제 제공 필드
  - `0B 주식체결`: 현재가, 등락율, **체결강도(228)**, 누적거래량, 누적거래대금, 당일 OHLC, **순매수체결량(1314)**
  - `0A 주식기세`: 현재가, 등락율, 누적거래량·대금, 당일 OHLC (체결강도 없음)
  - `0g 주식종목정보`: 상한가·하한가·기준가
  - `0J 업종지수` / `0U 업종등락`: 업종 현재가·등락율, 상승/하락/보합/상한/하한 종목수
  - `ka10173 조건검색 요청 실시간`: 일련번호, 종목코드, 삽입삭제 구분
- 요청 한도 오류 코드: `1700`(API별), `1701`(전체), `1702`(그룹). 수신 시 전체 레인을 잠시 멈추고 **한 번만** 재시도합니다.
- 토큰 만료 재시도 코드: `8005`, `8031`, `8103`(공식 클라이언트 상수). 실시간 로그인 실패 시 토큰을 강제 재발급해 **한 번만** 재로그인합니다.

### 제공되지 않아 **만들어내지 않는** 데이터

- **봉별 거래대금**: 어떤 실시간 타입에도 봉별 거래대금 필드가 없고 `ka10080`에도 없습니다. 따라서 수식 `ACCOUNT`/`거래대금`은 계속 `null`이며, 누적거래대금이나 가격×거래량으로 대체하지 않습니다.
- **투자자별(기관·외국인) 순매수**: REST 전용입니다. 실시간 `1314`는 **단일 체결의 순매수량**이라 투자자별 순매수와 다르며, 캐시에서도 별도 필드로 분리해 둡니다.
- **섹터별 주도종목**: 키움 명세에 해당 API가 존재하지 않습니다. 업종지수/업종등락만 제공하며, 주도종목을 자체 계산해 키움 데이터인 것처럼 표시하지 않습니다.

### 검증되지 않은 값 (사실로 표시하지 않음)

- 동시 실시간 **연결 수**와 **구독 최대 개수**: 공개 근거를 찾지 못했습니다. `KIWOOM_REALTIME_MAX_SUBSCRIPTIONS`(기본 100), `KIWOOM_REALTIME_MAX_ITEMS_PER_PACKET`(기본 10)은 **로컬 안전 한도**입니다.
- REST **초당/분당 수치 한도**: 코드만 공개되어 있습니다. 토큰 버킷 기본값은 보수적 추정입니다.
- **주문 요청 제한**: 주문 전송 자체가 구현되지 않아(`OrderGate`는 항상 거부) 검증할 수 없습니다.
- 실시간 `등락율`의 부호·고정소수점 표기: 명세에 명시가 없어, 소수점이 없고 6자리 이상인 값은 `ka10172`와 동일한 ×1000 고정소수점으로 해석합니다. 실계정 대조가 필요합니다.
- `843 삽입삭제 구분`의 값 의미: 문서에 없어 `I/D`류만 해석하고 그 외는 무시합니다.

### 감사와 장애 대응

- 모든 상태 전이·구독 변경·한도 오류·모의 신호·포지션 변경이 `/api/audit`와 `/api/state.audit`에 남습니다. 주문은 전송되지 않으며 이 사실도 `order` 카테고리에 기록됩니다.
- 재연결 후에는 보유 구독을 자동 복원하고, 세션 준비 시 콜백으로 스냅샷을 다시 채웁니다. 연속 중복 프레임은 TTL 중복 제거로 버립니다(억제 건수는 상태에 표시).
- 무응답 감시: 설정 시간 동안 프레임이 없으면 연결을 재설정합니다. 조용한 장에서는 정상 연결도 재설정될 수 있어 값은 보수적으로 두세요.
- 신호는 **확정 1분봉**에서만 계산하고 `(종목, 봉, 방향)` 단위로 한 번만 처리합니다. 지연·미래 봉은 차단하고 사유를 표시합니다.

### 테스트

`npm test`는 85개 테스트를 실행합니다. 실시간 관련 테스트는 **모의 WebSocket 서버**를 띄워 로그인·PING 에코·등록/해제·참조 카운트·중복 억제·끊김 후 재연결과 구독 복원·8005 토큰 만료 재시도·요청/응답·신호 중복 방지·지연/미래 봉 차단을 검증합니다. **실제 키움 서버·모의계좌로는 검증하지 못했습니다.**

## 수식 관리자

멀티 차트의 **수식 관리자**에서 지표, 신호, 강세, 시스템트레이딩 수식을 작성하고 저장할 수 있습니다. 활성화한 수식은 모든 차트에 동일하게 적용됩니다. 지표는 최대 5개 수식으로 구성할 수 있으며 각 수식은 동일한 지표변수를 사용합니다. 기본 수식과 추가 수식에 색상·표시 여부·선 종류·너비를 설정할 수 있으며 선 또는 막대 표시와 고정/기준값/직전 값 대비 색상 모드를 선택할 수 있고, 가격 차트 또는 지표별 별도 패널을 선택할 수 있습니다. 지표마다 선 종류·너비를 지정한 기준선을 최대 8개 추가할 수 있습니다. 표시 중인 수식 선이 없으면 기준선도 표시되지 않습니다. 신호는 확정봉 아래 화살표로, 강세는 해당 봉의 색상으로 표시됩니다. 강세 수식이 여러 개 참이면 목록의 첫 수식 색상을 사용합니다. 가격 차트에 표시하는 지표가 가격과 다른 단위이면 가격 축이 왜곡될 수 있으므로 별도 패널을 선택하세요. 시스템트레이딩은 매수/매도 조건을 각각 입력하며 활성화는 하나만 허용됩니다. 차트 표시와 중앙 모의 전략은 같은 수식을 사용하고 동시 매수/매도 신호는 무시합니다.

지원 데이터는 `O/OPEN/시가`, `H/HIGH/고가`, `L/LOW/저가`, `C/CLOSE/종가`, `V/VOLUME/거래량`, `ACCOUNT/거래대금`, `DATE/일자`, `TIME/시간`입니다. 날짜와 시간은 API 분봉의 타임스탬프를 한국 시간의 숫자 YYYYMMDD 및 HHMMSS로 변환한 것이며, 키움 HTS 봉 종료시각과의 일치는 검증되지 않았습니다. 분봉 응답에 거래량이 없으면 해당 값은 계산 불가(`null`)입니다. 산술·비교·논리 연산 외에 `A=avg(C,기간); A(1)` 형태의 변수 대입, 과거 봉 참조, `//` 한 줄 주석과 지표변수를 지원합니다. 지표변수는 수식 관리자에서 JSON 객체로 입력합니다. 함수: `MA(값,기간,단순|지수|가중[,과거봉])`, `AVG/SMA`, `WAVG`, `EAVG/EMA`, `STDEV`, `REF`, `IF`, `ABS`, `MAX`, `MIN`, `POW`, `LOG`, `LOG10`, `SQRT`, `SIN`, `COS`, `TAN`, `ASIN`, `ACOS`, `ATAN`, `HIGHEST`, `LOWEST`, `SUM`, `COUNT`, `COUNTSINCE`, `HIGHESTSINCE`, `LOWESTSINCE`, `BARSSINCE`, `VALUEWHEN`, `ROC`, `SHIFT/이동`, `DAYOPEN`, `DAYHIGH`, `DAYLOW`, `PREDAYOPEN`, `PREDAYHIGH`, `PREDAYLOW`, `PREDAYCLOSE`, `CROSSUP/상향돌파`, `CROSSDOWN/하향돌파`. 키움 설명서에 있는 일부 한글 함수명도 허용합니다. AVG, WAVG, EAVG, STDEV, HIGHEST, LOWEST, SUM은 세 번째 인자로 과거 봉을 지정할 수 있습니다. 기간은 1~500 정수 또는 지표변수이며 과거 봉 참조는 0도 허용합니다. EMA는 최초 기간의 단순평균으로 초기화합니다. WAVG는 최근 봉에 큰 가중치를 부여하고 STDEV는 모집단 표준편차를 사용합니다. LOG는 자연로그, `^`는 우결합 거듭제곱으로 구현했습니다. 이 계산 방식은 영웅문 실측과 대조하지 못했습니다. 값이 부족하거나 0으로 나누면 결과가 없으며 조건은 실행되지 않습니다. 예: `A=avg(C,단기); B=avg(C,장기); CrossUp(A,B)` (지표변수 `{"단기":5,"장기":20}`).

**이 구현은 키움 수식의 일부만 지원합니다. 100% 호환이 아닙니다.** 공식 [영웅문 수식관리자 설명서](https://download.kiwoom.com/hero4_help_new/pdf/012.pdf)를 참고했으나 함수별 계산값과 경계조건을 실제 영웅문과 대조하지 못했습니다. 지원 목록 외 함수, 미결제약정 등 추가 시장 데이터, 재귀 시계열 대입, 키움의 모든 라인 유형·색상 규칙·스케일 옵션, 매도 포지션의 모의 실시간 평가, 백테스트 최적화와 주문 설정 등은 지원되지 않습니다. 수식 검증 성공은 키움 호환이나 투자 성과의 보증이 아닙니다. 실거래 판단에 사용하지 마세요.

수식은 서버의 `data/formulas.json`에 저장됩니다(기본 경로, Git 제외). `FORMULAS_PATH`로 변경할 수 있습니다. 수식의 저장과 활성화는 실제 주문을 하지 않습니다. 시스템 전략은 확정된 1분봉만 평가하고 중복 평가를 방지하지만 데이터 지연/누락 시 모든 신호가 처리된다는 보장은 없습니다. 가상 포지션은 메모리에만 존재하며 재시작 시 초기화됩니다. 수식 수정 중에 이미 평가한 봉은 재평가하지 않습니다.

### 사용자 일반함수

수식 관리자 **일반함수**에서 함수명을 `MAO(단기,장기)`처럼 입력하고 본문에 `avg(C,단기)-avg(C,장기)`를 작성합니다. 같은 수식 세트의 지표·신호·강세·전략에서 `MAO(5,20)`으로 호출할 수 있으며 다른 사용자 함수에서 중첩 호출할 수 있습니다. 함수는 매개변수와 봉 필드만 참조하며, 매개변수는 값 또는 시계열입니다. 기간 인자로 사용할 경우에는 실제 값이 1~500인 정수여야 합니다. 빈 인자 목록도 허용합니다. 함수 이름과 인자는 다른 필드·내장 함수명과 중복할 수 없고, 순환 호출·미정의 함수·잘못된 인자 개수는 저장 시 거부합니다. 과도한 계산을 막기 위해 호출 깊이 16, 한 수식의 사용자 함수 호출 256회 제한이 있습니다.

키움 설명서의 일반함수 개념을 참고한 제한적 구현입니다. 선언·계산·이름 규칙이 영웅문과 완전히 동일하다고 검증되지 않았으며, 공유 함수 변경 후 저장할 때 이를 참조하는 모든 수식을 함께 검증합니다. 기존 전략 평가 및 실주문 제한은 그대로 적용됩니다.

### 백테스트 (실제 주문 없음)

시스템 수식에 선택적으로 매도 진입과 매도 청산을 **둘 다** 입력한 후 활성화하고 저장합니다. 차트의 백테스트 버튼은 현재 서버가 조회한 해당 종목의 확정 1분봉에 활성 전략을 적용합니다. 일반 모의 전략의 실시간 평가에는 매도 포지션을 적용하지 않습니다.

테스트는 확정봉 신호를 다음 봉의 시가에 1주 체결한 것으로 가정합니다. 매수와 매도 진입 신호가 동시에 발생하면 진입하지 않고, 보유 상태에서는 해당 방향의 청산만 처리하며 같은 봉에서 재진입하지 않습니다. 매수·매도·양방향을 선택하고 각 체결에 입력한 편도 비용과 불리한 방향의 슬리피지(bp)를 적용합니다. 선택적 손절·목표 수익률은 봉 종가에서 판정하여 다음 봉 시가에 청산합니다(0이면 미사용). 장중 고가/저가로 체결되었다고 가정하지 않으며 갭 때문에 설정한 비율과 실제 결과가 다를 수 있습니다. 미청산 포지션은 강제 청산하거나 실현 손익에 합산하지 않습니다. 결과에는 종목당 완료 거래, 실현 손익 기준 최대 낙폭과 미청산 방향이 표시됩니다. 미실현 손익을 포함한 최대 낙폭이 아닙니다. 주식의 실제 공매도 가능 여부, 대차 및 증거금, 시장 충격, 거래소별 호가, 세금 등은 모델링하지 않습니다. 신호가 마지막 봉에 발생하면 다음 봉이 없으므로 체결하지 않습니다.

백테스트는 현재 분봉 응답 한 페이지만 사용하며 장기간 검증이 아닙니다. 차트 시간 갭, 데이터 누락, 조건검색의 생존 편향 등이 결과에 영향을 줄 수 있습니다. 수식 계산과 결과는 키움 HTS에 대조되지 않았고 정확한 예측이나 실거래 근거가 아닙니다.

`DAYOPEN`, `DAYHIGH`, `DAYLOW`는 국내 정규장 09:00부터 해당 봉까지 결측 없이 연속된 1분봉이 있는 경우에만 계산합니다. 09:00 이전 봉이 있으면 09:00 봉에서 새로 시작합니다. 이력 첫 봉이 장중이거나 중간에 봉이 없으면 나머지 당일 값은 `null`입니다. 휴장·지연 개장·시간외 및 타 거래소 세션은 지원하지 않습니다. 이 보수적 처리와 시간 값의 의미는 HTS와 다를 수 있습니다. `SHIFT(A,N)`은 N>=0인 과거 방향 이동만 지원합니다. 미래 데이터를 참조하는 음수 이동은 백테스트 및 모의 전략에서 허용하지 않습니다.

차트에서 격자, 가격 로그 축, 높이를 일괄 선택할 수 있으며 이 설정은 브라우저의 현재 화면에만 적용됩니다. 백테스트 시작일과 종료일은 한국 시간 기준이며 현재 서버에 로드된 분봉 범위로 제한됩니다. 구간 밖 과거 봉은 지표의 초기 계산에만 사용되며, 시작일 이전 신호로 진입하지 않습니다.

### 전일 시세 및 봉별 거래대금

선택된 종목마다 키움 `ka10081` 일봉을 중앙 요청 큐로 조회해 분봉에 직전 거래일 시가·고가·저가·종가를 연결합니다. `PREDAYOPEN()`, `PREDAYHIGH()`, `PREDAYLOW()`, `PREDAYCLOSE()`에서 사용할 수 있습니다. 해당 분봉 날짜의 일봉과 직전 일봉이 모두 응답에 있어야 하며 누락된 값은 `null`입니다. 일봉은 최신 응답 한 페이지만 사용하므로 이전 이력이 응답 범위를 벗어나거나 당일 일봉이 없으면 전일 값도 `null`입니다. 휴일은 일봉 응답의 거래일 순서에 따릅니다. 분봉과 같은 수정주가 옵션을 사용하지만 권리 발생과 수정주가 적용, 누락·시간외·지연 상장 등에 대해 HTS와 동일함을 검증하지 못했습니다. 백테스트 시 조회 시점의 수정주가 일봉을 사용하므로 과거 시점에 알려진 데이터만 사용하는 것과 다를 수 있습니다. 일봉 조회가 실패하면 전체 갱신이 실패하고 이전 성공 데이터가 유지됩니다. 종목당 일봉 추가 요청으로 갱신이 더 오래 걸릴 수 있습니다.

`ACCOUNT`/`거래대금`은 **봉별 거래대금이 제공된 경우만** 계산하며, 공식 `ka10080` 분봉 응답에는 해당 필드가 없어 현재 실제 분봉에서는 항상 `null`입니다. 가격×거래량으로 임의 추정하지 않습니다. 조건검색 순위의 `ka10046` 누적거래대금은 백만원 단위의 누적값으로, 봉별 거래대금과 다르며 수식 필드에 대체하지 않습니다. 거래대금 수식을 실사용하려면 원 단위의 신뢰할 수 있는 봉별 데이터 소스와 누락·재연결 처리가 추가로 필요합니다.

### 데이터 지연 시 신호 차단

내부 모의 신호 평가는 가장 최근 확정 1분봉의 종료 시각이 현재보다 120초 이상 지연되면 해당 종목을 건너뜁니다(정확히 120초는 허용). 미래 시각의 봉도 차단하며 대시보드에 사유를 표시합니다. 장 종료나 거래 정지 시에도 신호가 중단될 수 있습니다. 이 검사는 연속성·거래소 상태·체결 데이터의 정확성을 보장하지 않습니다. 유효한 분봉이 하나도 없으면 조회를 실패 처리하며 잘못된 달력 날짜를 가진 봉은 버립니다. 이전 조회 결과가 남아 있을 수 있으므로 오류와 마지막 업데이트 시각을 확인하세요.

현재 전략의 '모의'는 앱 내부 신호와 가상 포지션일 뿐 키움 모의투자 계좌의 주문·체결이 아닙니다. 계좌 동기화, 중복 주문 방지, 위험 한도 및 실거래 주문은 구현·검증되지 않았습니다.
